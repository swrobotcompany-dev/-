# Qwen — инструкции для проекта «Тачка на прокачку»

## Контекст
- **GitHub:** `swrobotcompany-dev/-` (имя репозитория ровно `-`). Главная ветка — **main**, не `master`.
- Проект — локальная браузерная мини-игра, без npm, сборки и внешних зависимостей.
- Открывай `index.html` в браузере. При необходимости используй `python3 -m http.server 8000`.
- Не путай проект со `standoff`. Старый PR #1 (`2d-racing-game-refactoring-76fca`) содержит другую, конфликтующую реализацию: **не объединяй его автоматически**.

## Актуальная архитектура
- `index.html` — HTML-разметка гаража и тест-драйва; подключает JS и CSS.
- `assets/css/style.css` — стили гаража и режима тестирования, включая мобильную версию.
- `src/garage.js` — данные `CAR_PROFILES`, четыре индивидуальных SVG-кузова, диски, цвета, настройки и сохранение в `localStorage`.
- `src/testdrive.js` — физика движения, Canvas-трасса, управление, конусы, чекпоинты, таймер, рекорды кругов.
- `README.md` — запуск и кнопки.

## При работе над игрой
1. Изучи нужный файл и не переписывай весь проект без необходимости.
2. Если меняешь геометрию кузова: редактируй профиль модели в `CAR_PROFILES`; проверяй позиции колёс, арок, стекла, зеркал и освещения.
3. Если меняешь физику: проверь разгон, повороты на разных скоростях, тормоз, задний ход, заносы, выезд с трассы, сбивание конусов и полный круг.
4. После изменения проверь JavaScript-синтаксис, ссылки на ресурсы, загрузку в браузере и элементы управления. Не заявляй о выполненных тестах, если реально их не запускал.
5. Избегай внешних зависимостей. Не ломай сохранение выбранной машины и лучшего круга.
6. Если пользователь прямо просит внести изменения **сразу в main**, выполняй это. В остальных случаях новая ветка от актуальной `main`, затем PR в `main` с рабочей ссылкой.

## Работа с GitHub
- `master` давно не содержит новых изменений относительно `main`; никогда не открывай повторный PR `master → main`.
- Используй уже подключённое приложение GitHub в Qwen, если оно доступно.
- **Не проси пользователя присылать токены, PAT, API-ключи, GITHUB_TOKEN, GH_TOKEN, приватные ключи, cookie или пароли.** Не предлагай размещать их в чате/файлах.
- Если GitHub отклоняет создание PR, приводи **точный текст и код ошибки**; сначала проверь, что в новой ветке есть отличия от `main`.
- Если не работает встроенная интеграция, предложи пользователю проверить её в настройках Qwen — без передачи секретов.
- Не выполняй force-push, не сливай чужие конфликтующие ветки, не удаляй историю без просьбы.
